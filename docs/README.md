# Учебник по «Прилавку»

Админка интернет-магазина, написанная так, чтобы по ней можно было учиться. Главная тема —
**WebSocket по-взрослому**: не «открыл сокет и слушаю», а переподключение, проверка связи,
докачка пропущенного, подтверждения и синхронизация с кэшем запросов.

Читать по порядку, рядом открыв код: в начале каждого файла комментарий объясняет «почему так».

## Как учиться на этом проекте

1. **Запустите и откройте экран «Соединение»** (глава 01). Нажмите «Оборвать» и прочитайте
   журнал кадров сверху вниз — там вся глава 04 и 05 в десяти строках.
2. **Пройдите [лабораторные](labs.md)** — по одной, сверяясь с главами.
3. **Запустите настоящий сервер** (`npm run server` + `npm run dev:real`), откройте два окна
   под разными ролями и один и тот же заказ. Смените статус в одном окне. Откройте
   DevTools → Network → WS → Messages и посмотрите на кадры.
4. **Читайте код в таком порядке:**
   `src/shared/protocol.ts` → `src/realtime/backoff.ts` → `socket.ts` → `client.ts` →
   `src/backend/hub.ts` → `src/realtime/sync.ts`. Рядом с каждым — файл `*.test.ts`: тесты
   читаются как список требований.
5. **Сломайте и почините.** Идеи по возрастанию сложности:
   - поменяйте `PING_INTERVAL` на 3 секунды и посмотрите в журнал;
   - уберите `jitter` из `backoff.ts` — какой тест упадёт?
   - добавьте событие `order.deleted`: тип в `protocol.ts`, публикация в `api.ts`,
     обработчик в `sync.ts`;
   - добавьте индикатор «печатает…» в заметках (событие-состояние, как `presence`);
   - синхронизируйте вкладки через `BroadcastChannel`, чтобы на все вкладки было одно
     соединение;
   - замените хаб в памяти на Redis pub/sub (глава 06, раздел про масштабирование).
6. `npm run check` — линтер, типы, 138 тестов и сборка скажут, если что-то сломалось.
