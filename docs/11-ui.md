# 11. Интерфейс: shadcn/ui, тема, права, доступность

## shadcn/ui — не библиотека

Обычная библиотека компонентов ставится из npm и живёт в `node_modules`. shadcn/ui
**копирует исходники компонентов в проект** (`src/components/ui/`):

```bash
npx shadcn@latest add dialog table sidebar
```

| | Библиотека (MUI, Ant) | shadcn/ui |
| --- | --- | --- |
| Где код | `node_modules` | в вашем репозитории |
| Изменить компонент | переопределять стили, бороться с API | открыть файл и поправить |
| Обновления | `npm update` | вручную, компонент за компонентом |
| Размер сборки | вся библиотека или tree-shaking | только добавленное |

Под капотом — Radix UI: примитивы без стилей, но с правильным поведением (фокус в модальном
окне, клавиатура в меню, ARIA-атрибуты). Самая трудная часть компонентов — доступность —
уже сделана.

Папка `src/components/ui/` — сгенерированный код: линтер и Prettier её пропускают.

## Tailwind 4: тема на CSS-переменных

`src/index.css`:

```css
:root  { --background: oklch(0.985 0.003 75); --primary: oklch(0.58 0.16 45); … }
.dark  { --background: oklch(0.16 0.004 60);  --primary: oklch(0.72 0.15 55); … }

@theme inline { --color-primary: var(--primary); --color-success: var(--success); … }
```

- Компоненты пишут `bg-primary text-muted-foreground` — имена **ролей**, а не цветов.
  Сменить фирменный цвет — одна строка.
- Тёмная тема — класс `.dark` на `<html>`: переменные переопределяются, интерфейс
  перекрашивается без JavaScript в компонентах. Графики тоже: Recharts рисует SVG, а в SVG
  `var(--chart-1)` работает так же.
- `oklch` — цветовая модель, где «светлота» соответствует восприятию: у двух цветов с
  одинаковой L одинаковая видимая яркость. Удобно подбирать пары для тёмной темы.
- Свои токены (`--success`, `--warning`, `--info`) добавлены рядом с токенами shadcn — для
  статусов заказов.

### Тема без мигания

`src/lib/theme.ts` + скрипт в `index.html`. Класс `.dark` ставится **до первой отрисовки**
— маленьким скриптом в `<head>`, ещё до загрузки React. Иначе тёмная тема мигала бы белым
экраном. «Как в системе» следит за `prefers-color-scheme` и переключается вечером само.

## Каркас

`_app.tsx`: боковое меню (shadcn `Sidebar`) — на компьютере сворачивается до значков, на
телефоне превращается в выезжающую панель. Шапка «липкая», в ней индикатор соединения и
уведомления.

Вёрстка — сеткой, которая сама перестраивается: `grid sm:grid-cols-2 xl:grid-cols-4`.
Таблицы на телефоне прокручиваются по горизонтали **внутри своей карточки** — страница вбок
не уезжает (`min-w-0` у контейнеров; без него элемент сетки не может стать уже содержимого).

## Права доступа (RBAC)

`src/shared/permissions.ts`:

```ts
const BY_ROLE: Record<Role, readonly Permission[]> = {
  admin: PERMISSIONS,
  manager: ['orders.update', 'orders.note', 'products.create', 'products.update', 'customers.view'],
  viewer: ['customers.view'],
}
export const can = (role, permission) => BY_ROLE[role].includes(permission)
```

**Код проверяет право, а не роль.** Не `if (user.role === 'admin')`, а
`can(role, 'products.delete')`. Появится роль «старший менеджер» — меняется одна таблица.

Проверка — в трёх местах:

| Где | Как | Зачем |
| --- | --- | --- |
| Компонент | `useCan('orders.update')` → не рисовать кнопку | не предлагать невозможное |
| Маршрут | `beforeLoad` → `redirect` | не пускать на экран |
| **Сервер** | `route(…, { permission })` → 403; в обработчике сокета → `HubError('forbidden')` | **единственная настоящая защита** |

Файл лежит в `shared`: клиент и сервер пользуются одной таблицей и не могут разойтись.
На экране «Настройки» она показана целиком.

Порядок ответов сервера: сначала «кто ты» (401), потом «можно ли тебе» (403).

## Доступность

| Что | Где |
| --- | --- |
| Семантика: `<main>`, `<header>`, `<nav>`, заголовки по уровням | каркас, экраны |
| Всё доступно с клавиатуры, фокус виден | компоненты Radix + `focus-visible:ring` |
| У кнопок-значков есть имя | `aria-label="Следующая страница"` |
| Цвет не единственный признак | статус — точка **и** текст; остаток — цвет **и** «мало» |
| Графики имеют текстовую замену | `role="img"` + `aria-label` с цифрами; легенда — настоящая таблица значений |
| Сортировка | `aria-sort` на заголовке столбца |
| Формы | `label`, `aria-invalid`, `aria-describedby`, `role="alert"` |
| Живые области | `role="status"` у баннеров; `aria-live` у заметок; у метрик — намеренно нет |
| Движение | анимации выключаются при `prefers-reduced-motion` |
| Опасные действия | `AlertDialog` с понятными кнопками («Не отменять» / «Отменить заказ»), а не «Да / Нет» |

## Состояния экрана

У каждого списка — четыре состояния, и все нарисованы:

- **загрузка** — скелет той же формы, что и содержимое (ничего не прыгает);
- **ошибка** — что случилось и кнопка «Повторить»;
- **пусто** — что это значит и что делать («Попробуйте изменить запрос»);
- **данные**.

Плюс пятое, особенное для реального времени: **«данные могут быть неактуальны»** — полоса
и приглушённые живые блоки, когда соединения нет.

## Тексты

- Кнопка называет действие: «Отметить оплаченным», а не «ОК».
- Ошибка говорит, что делать: «Старая цена должна быть выше текущей».
- Числа и даты — через `Intl` (`lib/format.ts`): «1 214 140 ₽», «5 минут назад»,
  «1 781 заказ / 2 заказа / 5 заказов».
