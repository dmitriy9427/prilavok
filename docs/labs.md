# Лабораторные: WebSocket руками

Девять опытов. Для каждого — что сделать, что увидеть и какую главу он иллюстрирует.
Опыты 1–7 — в обычном режиме (`npm run dev`), 8–9 — с настоящим сервером.

Откройте экран **«Соединение»**. Переключатель «Скрыть ping, pong и метрики» поначалу
оставьте включённым.

Как читать журнал: ↑ — отправили мы, ↓ — пришло от сервера, ⊙ — событие самого соединения
(открылось, закрылось, ждём повтора).

## 1. Рукопожатие

**Сделать:** обновить страницу (F5), открыть «Соединение», прокрутить журнал в начало.

**Увидеть:**

```
⊙ open      Соединение открыто
↑ hello     {"t":"hello","v":1,"token":"•••","channels":["orders","notifications"],"resume":null}
↓ welcome   {"t":"welcome","sessionId":"s1",…,"epoch":"…","seq":0,"resumed":true,…}
```

**Понять:** до `welcome` клиент ничего не шлёт. Токен в журнале скрыт. `resume: null` —
первое подключение. → [глава 03](03-protocol.md)

## 2. Каналы меняются на ходу

**Сделать:** перейти на «Дашборд», подождать пару секунд, вернуться на «Соединение».

**Увидеть:** `↑ sub … "channel":"metrics"` → `↓ ack`, а после ухода с дашборда —
`↑ unsub … "metrics"`. В блоке «Каналы» — `metrics` появлялся и исчез.

**Понять:** соединение одно, подписки — по потребности экранов. Отписка уходит с задержкой
300 мс. → главы [03](03-protocol.md), [07](07-cache-sync.md)

## 3. Heartbeat

**Сделать:** выключить «Скрыть ping, pong и метрики», подождать 15 секунд.

**Увидеть:** `↑ ping {"ts":…}` → `↓ pong {"ts":…,"seq":…}` каждые 15 с. «Задержка» в карточке
обновляется.

**Понять:** `pong` несёт текущий номер события — клиент сдвигает закладку, даже когда в его
каналах тихо. → [глава 04](04-reconnect.md)

## 4. Обрыв и докачка

**Сделать:** запомнить «Номер события». Нажать **«Оборвать»** и сразу дважды **«Создать»**.

**Увидеть:**

```
⊙ close     Соединение закрыто: код 4999 — закрыто клиентом
⊙ retry     Повтор №1 через 0.4 с
⊙ open      Соединение открыто
↑ hello     {…,"resume":{"epoch":"…","seq":12}}
↓ welcome   {…,"seq":14,"resumed":true}
↓ order.created  {…,"seq":13,…}
↓ order.created  {…,"seq":14,…}
```

«Переподключений» = 1, «Полных обновлений» = 0, бейдж «Заказы» в меню вырос на 2.

**Понять:** два заказа были созданы, пока связи не было, — и всё равно дошли. Ни одного
HTTP-запроса. → [глава 05](05-resume.md)

## 5. Перезапуск сервера

**Сделать:** запомнить «Эпоху». Нажать **«Перезапустить»**.

**Увидеть:** `close` с кодом 4000 «сервер перезапускается» → `hello` с прежней эпохой →
`welcome` с **новой** эпохой и `"resumed":false` → `⊙ resync`. Тост «Связь восстановлена.
Данные обновлены». «Полных обновлений» = 1. В DevTools → Network — пачка HTTP-запросов.

**Понять:** сервер не может дослать события прошлой «жизни» — клиент перезапрашивает всё,
что на экране. → [глава 05](05-resume.md)

## 6. Сервер молчит

**Сделать:** выключить скрытие ping. Включить **«Сервер молчит»**. Ждать до 20 секунд.

**Увидеть:** индикатор в шапке всё это время — «На связи» (!). Потом:

```
⊙ heartbeat  Нет pong — считаем соединение мёртвым
⊙ close      … код 4999
⊙ retry      Повтор №1 через 0.4 с
↑ hello      …
⊙ retry      Повтор №2 через 0.9 с       ← welcome не приходит: паузы растут
```

Через 1,5 с — жёлтая полоса «Нет связи с сервером. Попытка N через M с». Выключите
переключатель — следующий `hello` получит `welcome`.

**Понять:** без heartbeat клиент показывал бы «на связи» бесконечно. И: счётчик попыток
сбрасывается только после `welcome`, а не после `open`. → [глава 04](04-reconnect.md)

## 7. Нет сети

**Сделать:** включить **«Нет сети»**, подождать, выключить.

**Увидеть:** состояние `offline`, строк `retry` в журнале **нет**. После выключения —
мгновенное подключение (без паузы) и `resumed: true`.

**Понять:** когда известно, что сети нет, попытки не тратятся. То же произойдёт, если
выключить Wi-Fi: браузер пришлёт событие `offline`. → [глава 04](04-reconnect.md)

## 8. Два пользователя (настоящий сервер)

**Сделать:** `npm run server` и `npm run dev:real`. Открыть приложение в обычном окне
(Администратор) и в окне инкогнито (Менеджер). В обоих — один и тот же заказ в статусе
«Новый».

**Увидеть:**

- в каждом окне: «<имя> тоже смотрит этот заказ»;
- сменить статус в первом — во втором обновились бейдж и история, пришёл тост;
- написать заметку во втором — она появилась в первом;
- закрыть второе окно — в первом аватар коллеги исчез;
- в терминале сервера — журнал запросов и подключений.

**Понять:** кэш второго окна обновлён событием, HTTP-запроса не было. Присутствие привязано
к соединению. → главы [06](06-server.md), [07](07-cache-sync.md)

## 9. Кадры в DevTools и конфликт версий (настоящий сервер)

**Сделать:**

1. DevTools → Network → WS → выбрать `ws` → Messages. Походить по экранам.
2. Вкладка Headers того же запроса: `Upgrade: websocket`, ответ `101 Switching Protocols`.
3. Остановить сервер (Ctrl+C). В Messages — закрытие с кодом 4000. Запустить снова.
4. Конфликт версий: в двух окнах открыть один заказ «Новый». В первом окне включить
   в DevTools Network → Offline (сокет оборвётся, кэш останется старым). Во втором сменить
   статус. В первом выключить Offline и сразу, не дожидаясь обновления, нажать кнопку статуса.

**Увидеть:** в шаге 3 — после запуска новая эпоха и полный перезапрос. В шаге 4 — либо
клиент успел докачать событие (и кнопка уже другая), либо сервер ответил `409`: «Заказ уже
изменил кто-то другой. Данные обновлены».

**Понять:** настоящие кадры выглядят так же, как в журнале приложения. Версия записи не
даёт молча затереть чужую правку. → главы [02](02-websocket-basics.md), [07](07-cache-sync.md)
