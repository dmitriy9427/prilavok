# Уроки: найденные баги

Двенадцать ошибок, пойманных при разработке «Прилавка». У каждой — что было видно, причина,
исправление и вывод.

## 1. Схема, которая не пропускала ни одного кадра

**Видно:** клиент подключается, шлёт `hello`, сервер отвечает `welcome` — а клиент остаётся
в «Подключение…». 20 из 27 тестов клиента красные.

**Причина:** кадры сервера описаны как `z.discriminatedUnion('t', […])`, а у `ack` два
варианта (успех и ошибка) с одним и тем же `t: 'ack'`. Размеченное объединение требует
уникальных значений — zod бросал исключение при **любом** разборе, а `decode()` ловил его и
возвращал `null`: «мусор».

**Исправление:** обычный `z.union`.

**Урок:** `catch`, который превращает любую ошибку в «неверные данные», скрывает ошибки в
собственном коде. И: баг нашли тесты за секунду — в браузере это выглядело бы как «сокет
почему-то не работает».

## 2. Тесты мешали друг другу

**Видно:** тест «вкладку снова открыли — подключается сразу» ждёт 2 сокета, получает 5.

**Причина:** `ReconnectingSocket.start()` вешает обработчики на `document` и `window`.
Сокеты из предыдущих тестов никто не останавливал — их обработчики остались и сработали.

**Исправление:** `afterEach` останавливает всё созданное.

**Урок:** это не «проблема тестов» — тест показал настоящую утечку. Всё, что подписывается
на глобальные события, обязано уметь отписываться (`stop()`), и это нужно вызывать.

## 3. Причина обрыва затиралась

**Видно:** после «нет pong» в интерфейсе причина — «закрыто клиентом» вместо «Сервер не
отвечает на ping».

**Причина:** heartbeat записывал причину и вызывал `reconnect()`; обработчик закрытия
перезаписывал её общим текстом для кода 4999.

**Исправление:** для своего кода закрытия сохраняем уже записанную причину.

**Урок:** когда сообщение формируется в двух местах, побеждает последнее — обычно менее
конкретное.

## 4. Ошибка в консоли от чужого `<script>`

**Видно:** React 19 пишет в консоль: «Encountered a script tag while rendering React
component».

**Причина:** сначала подозрение пало на библиотеку тем `next-themes` (она вставляет скрипт).
Заменил её своим модулем — ошибка осталась. Настоящий источник — опция роутера
`scrollRestoration: true`: она рендерит `<script>` для серверного рендеринга.

**Исправление:** опция убрана; прокрутка к началу при смене экрана — три строки в `main.tsx`.
Свой модуль темы остался: он короче зависимости.

**Урок:** проверяйте гипотезу до исправления. «Удалил подозреваемого — не помогло» стоило
времени; поиск по `node_modules` слова `script` занял бы минуту.

## 5. `useEffectEvent` в таймере

**Видно:** линтер: «функция из useEffectEvent может вызываться только из эффектов».

**Причина:** в `useDebouncedInput` обработчик вызывался из `setTimeout`, запущенного
обработчиком ввода.

**Исправление:** классический «ref с последним значением»: `latest.current = onCommit` в
эффекте, вызов `latest.current(…)` в таймере.

**Урок:** у новых API React узкая область применения. `useEffectEvent` — для эффектов;
для колбэков из обработчиков событий по-прежнему ref.

## 6. Лишние `sub` / `unsub` при каждом переходе

**Видно:** в журнале кадров при переходе «Товары → товар»: `unsub products`, `sub products`,
`unsub products`, `sub products`.

**Причина:** первый экран размонтировался и отписался, второй тут же подписался. Плюс React
StrictMode в разработке запускает эффекты дважды.

**Исправление:** отписка от сервера откладывается на 300 мс; если за это время появился
новый слушатель — отменяется.

**Урок:** журнал кадров на экране — не украшение. Без него этот шум никто бы не заметил, а
между `unsub` и `sub` можно потерять событие.

## 7. «Изменения не сохранены» сразу после сохранения

**Видно:** создаю товар — остаюсь на форме создания; в браузере вопрос «Уйти со страницы?».

**Причина:** после успеха вызывались `reset(values)` и переход на страницу товара. Но
`isDirty`, который читает охранник `useBlocker`, обновится только после перерисовки, а
переход происходит в том же тике.

**Исправление:** флаг `justSaved` в `ref` — он меняется мгновенно.

**Урок:** состояние React — снимок на момент рендера. Всё, что должно быть прочитано «прямо
сейчас, до перерисовки», живёт в ref.

## 8. Созданный товар пропадал после F5

**Видно:** создал товар, обновил страницу — его нет.

**Причина:** снимок базы пишется в `sessionStorage` с задержкой (чтобы не писать на каждое
событие симулятора). Перезагрузка в течение этой секунды — и запись не случилась.

**Исправление:** задержка меньше + запись по событию `pagehide`.

**Урок:** у любого debounce есть «хвост», который теряется при закрытии. Отложенную запись
нужно уметь завершить немедленно.

## 9. Все остатки мигали при открытии списка

**Видно:** захожу на «Товары» — подсвечиваются все ячейки остатков.

**Причина:** подсветка изменений сделана CSS-анимацией при создании элемента. При первом
показе создаются все элементы.

**Исправление:** запоминаем значение при появлении строки и подсвечиваем только отличие от
него; для заказов — только события последних 2,5 секунд.

**Урок:** «анимация при появлении» и «анимация при изменении» — разные условия.

## 10. Невидимый символ в исходнике

**Видно:** линтер: «irregular whitespace» в `format.ts`.

**Причина:** в начало CSV добавляется BOM (иначе Excel портит кириллицу). В файл попал сам
символ вместо записи `﻿`.

**Исправление:** escape-последовательность.

**Урок:** невидимые символы пишут escape-кодом — иначе их не видно в ревью и легко потерять
при правке.

## 11. API библиотек не такие, как в статьях

**Видно:** `onUnhandledRequest` не существует (MSW 3 — теперь `onUnhandledFrame`, потому что
обрабатываются и сокеты); `VisibilityState` не экспортируется (Table 9 —
`ColumnVisibilityState`); `ws` импортируется из `msw/ws`.

**Причина:** мажорные версии вышли недавно, примеры в сети — для старых.

**Исправление:** читать `.d.ts` и документацию **в `node_modules`** — у TanStack Table 9 она
лежит прямо в пакете.

**Урок:** источник правды — установленная версия, а не поиск. (Тот же урок, что и в «Ритме».)

## 12. Грамматика в данных

**Видно:** «продано 101 штука».

**Причина:** функция склонения верно выбрала «штука» для 101 — но фраза требует другого
падежа («продано 101 штуку»).

**Исправление:** «продано 101 шт.»

**Урок:** склонение по числу не решает падежи. Когда фраза сложная — перестройте её так,
чтобы слово не склонялось.
