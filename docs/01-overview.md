# 01. Обзор и запуск

## Что это

«Прилавок» — админка магазина кофе, чая и посуды.

| Экран | Что на нём | Чему учит |
| --- | --- | --- |
| Дашборд | Живые цифры, выручка, статусы, лента заказов | события-состояния, графики, загрузчики |
| Заказы | Таблица на 1 800 строк: фильтры, сортировка, страницы, массовые действия | серверная таблица, состояние в адресе |
| Заказ | Состав, статус, история, заметки, «кто сейчас смотрит» | оптимистичные обновления, присутствие, запрос-ответ по сокету |
| Товары | Каталог, форма с вариантами | формы, проверка на клиенте и сервере |
| Клиенты | 10 000 строк без пагинации | бесконечная подгрузка + виртуализация |
| Соединение | Состояние сокета, журнал кадров, кнопки «сломать» | всё про WebSocket |
| Настройки | Тема, таблица прав | роли |

Три роли: администратор, менеджер, наблюдатель — у каждой свои права.

## Запуск

```bash
npm install
npm run dev
```

Откроется http://localhost:5173. Сервера нет: его изображает код в браузере.

### Второй режим — настоящий сервер

В двух терминалах:

```bash
npm run server
```

```bash
npm run dev:real
```

Первый запускает Node-сервер на порту 8787 (HTTP + WebSocket), второй — интерфейс,
подключённый к нему (адреса — в `.env.real`).

| | Мок (`npm run dev`) | Настоящий сервер (`npm run dev:real`) |
| --- | --- | --- |
| Сервер | MSW в браузере | Node.js + библиотека `ws` |
| Данные | свои у каждой вкладки | общие для всех вкладок и браузеров |
| Кадры в DevTools → WS | не видны (сети нет) | видны |
| Два пользователя | нет | да: откройте два окна |
| Работает на GitHub Pages | да | нет |

Логика сервера в обоих режимах **одна и та же** (`src/backend`). Отличается только
«проводка» — кто доставляет запросы и кадры.

## Как устроено

```
┌──────────────────────── браузер ────────────────────────┐
│                                                         │
│  экраны (src/routes, src/features)                      │
│      │ читают                       ▲ перерисовка       │
│      ▼                              │                   │
│  кэш запросов (TanStack Query) ◀── sync.ts ◀── события  │
│      │ fetch                                    ▲       │
│      ▼                                          │       │
│  api/http.ts                          realtime/client.ts│  протокол
│      │                                          │       │
│      │                                realtime/socket.ts│  транспорт
└──────┼──────────────────────────────────────────┼───────┘
       │ HTTP                          WebSocket  │
┌──────▼──────────────────────────────────────────▼───────┐
│  переходник: MSW (src/mocks)  или  Node (server/)       │
├─────────────────────────────────────────────────────────┤
│  src/backend:  api.ts ──▶ db.ts ◀── simulator.ts        │
│                   └──────▶ hub.ts ◀──────┘              │
└─────────────────────────────────────────────────────────┘
        src/shared — типы, протокол, схемы, права (общие)
```

Главная мысль: **интерфейс читает данные только из кэша**. Откуда они туда попали — из
HTTP-ответа или из события сокета — экрану безразлично.

## Карта проекта

```
src/
├── shared/            общее для клиента и сервера
│   ├── types.ts         заказ, товар, клиент…
│   ├── protocol.ts      протокол WebSocket          ← начать отсюда
│   ├── schemas.ts       проверка форм (zod)
│   └── permissions.ts   роли и права
│
├── realtime/          клиент реального времени
│   ├── backoff.ts       пауза перед повтором
│   ├── socket.ts        транспорт: переподключение
│   ├── client.ts        протокол: каналы, запросы, докачка
│   ├── instance.ts      единственный экземпляр, привязка ко входу
│   ├── hooks.ts         useChannel, useRealtimeEvent, useRealtimeStatus
│   ├── sync.ts          события → кэш запросов
│   └── live.ts          живое состояние (метрики, счётчики)
│
├── backend/           «сервер» (работает и в браузере, и в Node)
│   ├── hub.ts           серверная половина WebSocket
│   ├── api.ts           REST
│   ├── db.ts            база в памяти
│   ├── seed.ts          демо-данные
│   └── simulator.ts     «жизнь» магазина
│
├── mocks/browser.ts   переходник MSW
├── api/               HTTP-клиент, запросы, мутации
├── routes/            экраны (файл = адрес)
├── features/          части экранов: таблица заказов, форма товара…
├── components/        общие компоненты; ui/ — shadcn
└── lib/               формат, авторизация, тема, хранилище
server/index.ts        настоящий сервер на Node
```

Рядом с кодом лежат тесты (`*.test.ts`) — 138 штук.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | интерфейс + сервер-мок в браузере |
| `npm run server` | настоящий сервер (перезапускается при правке кода) |
| `npm run dev:real` | интерфейс, подключённый к настоящему серверу |
| `npm test` | тесты |
| `npm run check` | линтер + типы + тесты + сборка |
| `npm run build` | сборка в `dist/` |

## Версии

React 19 · TypeScript 6 · Vite 8 · TanStack Router / Query 5 / Table 9 / Virtual 3 ·
Tailwind 4 · shadcn/ui · react-hook-form + zod 4 · Recharts 3 · MSW 3 · `ws` 8 · Vitest 5.
Node.js 24 запускает TypeScript без сборки — поэтому `server/index.ts` стартует командой
`node server/index.ts`.
